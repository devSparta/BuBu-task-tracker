# Domain model

## Назначение документа

Документ описывает предметную область таск-трекера: сущности, их связи, допустимые состояния и бизнес-инварианты. Это концептуальная модель, а не готовая схема PostgreSQL. Физические таблицы, типы колонок, индексы и внешние ключи будут спроектированы отдельно на её основе.

Главная цель модели — определить правила, которые система обязана сохранять независимо от HTTP API, интерфейса и способа хранения данных.

## Термины

| Термин | Значение |
|---|---|
| Пользователь | Глобальная учётная запись человека |
| Рабочее пространство | Изолированная область одной команды или организации |
| Участник | Связь пользователя с рабочим пространством и его ролью |
| Проект | Контейнер для задач и спринтов внутри рабочего пространства |
| Backlog | Задачи проекта, не включённые в спринт; это не статус задачи |
| Спринт | Ограниченный период планирования задач проекта |
| Задача | Единица работы с исполнителем, статусом, приоритетом и сроком |
| Постановщик | Пользователь, создавший задачу |
| Исполнитель | Пользователь, ответственный за выполнение задачи |
| Наблюдатель | Пользователь, подписанный на изменения задачи |
| Бизнес-инвариант | Правило, которое должно оставаться истинным после любой операции |

## Справочники состояний

### Роли рабочего пространства

| Значение | Назначение |
|---|---|
| `OWNER` | Управление рабочим пространством, владельцами и всеми ресурсами |
| `ADMIN` | Управление участниками, проектами, спринтами и задачами без управления владельцами |
| `MEMBER` | Работа с задачами, наблюдателями и комментариями |
| `VIEWER` | Доступ только для чтения |

### Состояния спринта

| Значение | Назначение |
|---|---|
| `PLANNED` | Спринт создан, но ещё не начат |
| `ACTIVE` | Текущий спринт проекта |
| `COMPLETED` | Спринт завершён и больше не изменяется |

### Статусы задачи

| Значение | Назначение |
|---|---|
| `TODO` | Работа ещё не начата |
| `IN_PROGRESS` | Задача выполняется |
| `REVIEW` | Результат ожидает проверки |
| `DONE` | Работа завершена |

### Приоритеты задачи

`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.

## Переходы задачи

![ЖизненныйЦиклЗадачи](C:\BuBu-task-tracker\docs\ЖизненныйЦиклЗадачи.svg)

Прямые переходы `TODO → DONE` и `IN_PROGRESS → DONE` запрещены. Возврат из `DONE` считается повторным открытием задачи и обязательно записывается в историю.

## Сущности

### User

Глобальная учётная запись, не принадлежащая конкретному рабочему пространству.

Основные данные:

- идентификатор;
- нормализованный email;
- отображаемое имя;
- хеш пароля;
- состояние учётной записи;
- время создания и последнего изменения.

Инварианты:

- нормализованный email уникален в системе;
- пароль никогда не хранится и не журналируется в открытом виде;
- заблокированный пользователь не может создавать новые сессии;
- блокировка пользователя не удаляет созданные им задачи, комментарии и события.

### Session

Серверная пользовательская сессия.

Основные данные:

- владелец сессии;
- хеш случайного токена;
- время создания и истечения;
- время отзыва, если сессия отозвана;
- технические метаданные устройства без хранения лишних персональных данных.

Инварианты:

- исходный токен не хранится в базе данных;
- просроченная или отозванная сессия не принимается;
- выход пользователя отзывает текущую сессию;
- смена пароля позволяет отозвать все активные сессии пользователя.

### Workspace

Граница изоляции данных одной команды.

Основные данные:

- идентификатор;
- название;
- уникальный slug;
- время создания.

Инварианты:

- рабочее пространство всегда имеет хотя бы одного активного владельца;
- удалить, исключить или понизить в роли последнего владельца нельзя;
- пользователь получает доступ только через активное членство;
- ресурсы одного рабочего пространства недоступны участникам другого.

### WorkspaceMembership

Связь пользователя с рабочим пространством.

Основные данные:

- пользователь;
- рабочее пространство;
- роль;
- время вступления.

Инварианты:

- пара «пользователь + рабочее пространство» уникальна;
- назначаемый пользователь должен существовать и быть активным;
- роль принадлежит фиксированному набору `OWNER`, `ADMIN`, `MEMBER`, `VIEWER`;
- изменение роли владельца не должно оставлять рабочее пространство без владельца.

### WorkspaceInvitation

Одноразовое приглашение пользователя по email.

Основные данные:

- рабочее пространство;
- нормализованный email получателя;
- назначаемая роль;
- хеш случайного токена;
- автор приглашения;
- срок действия;
- состояние `PENDING`, `ACCEPTED` или `REVOKED`.

Инварианты:

- принимать можно только приглашение в состоянии `PENDING` с неистёкшим сроком;
- токен одноразовый и хранится только в виде хеша;
- принять приглашение может пользователь с совпадающим нормализованным email;
- принятие приглашения создаёт членство и переводит приглашение в `ACCEPTED` одной транзакцией;
- приглашение не может назначать роль `OWNER`; владельца назначает существующий владелец отдельной операцией.

### Project

Контейнер задач и спринтов внутри рабочего пространства.

Основные данные:

- рабочее пространство;
- название;
- короткий ключ проекта для человекочитаемых номеров задач;
- следующий порядковый номер задачи;
- время архивирования, если проект архивирован.

Инварианты:

- ключ проекта уникален внутри рабочего пространства и не меняется после создания первой задачи;
- все активные участники рабочего пространства могут видеть неархивированные проекты;
- архивированный проект доступен только для чтения;
- в архивированном проекте нельзя создавать задачи и спринты;
- проект нельзя перенести в другое рабочее пространство.

### Sprint

Период планирования внутри одного проекта.

Основные данные:

- проект;
- название;
- цель;
- состояние;
- планируемые и фактические даты начала и завершения.

Инварианты:

- спринт и все его задачи принадлежат одному проекту;
- в одном проекте одновременно активен не более чем один спринт;
- начать можно только спринт в состоянии `PLANNED`;
- завершить можно только спринт в состоянии `ACTIVE`;
- завершённый спринт нельзя снова активировать;
- завершённые задачи сохраняют связь с завершённым спринтом;
- незавершённые задачи при завершении спринта возвращаются в backlog;
- спринты архивированного проекта не изменяются.

### Issue

Единица работы внутри проекта.

Основные данные:

- проект;
- неизменяемый порядковый номер внутри проекта;
- заголовок и Markdown-описание;
- статус и приоритет;
- постановщик;
- необязательный исполнитель;
- необязательный спринт;
- необязательный дедлайн;
- версия для защиты от потерянных обновлений;
- время создания, изменения и архивирования.

Человекочитаемый ключ формируется из ключа проекта и номера задачи, например `CORE-42`.

Инварианты:

- пара «проект + порядковый номер» уникальна и неизменяема;
- постановщик является активным участником рабочего пространства проекта;
- исполнитель, если назначен, является активным участником того же рабочего пространства;
- спринт, если назначен, принадлежит тому же проекту;
- отсутствие спринта означает нахождение задачи в backlog;
- дедлайн может находиться в прошлом: такая задача считается просроченной, а не невалидной;
- статус изменяется только по разрешённым переходам;
- любое изменение статуса, исполнителя, приоритета, дедлайна или спринта создаёт событие истории;
- обновление принимается только для ожидаемой версии задачи;
- архивированная задача доступна только для чтения;
- физическое удаление задачи через пользовательские сценарии запрещено.

### IssueWatcher

Подписка участника на изменения задачи.

Инварианты:

- пара «задача + пользователь» уникальна;
- наблюдатель является активным участником рабочего пространства задачи;
- постановщик и исполнитель могут одновременно быть наблюдателями;
- повторная подписка идемпотентна и не создаёт дубликат.

### Comment

Сообщение участника внутри задачи.

Основные данные:

- задача;
- автор;
- текст в Markdown;
- время создания.

Инварианты:

- автор является активным участником рабочего пространства задачи;
- комментировать архивированную задачу нельзя;
- пустой комментарий запрещён;
- редактирование и удаление комментариев не входят в MVP.

### IssueEvent

Неизменяемая запись истории задачи.

Основные данные:

- задача;
- инициатор, если действие выполнено пользователем;
- тип события;
- безопасный снимок изменённых полей до и после операции;
- время события.

Инварианты:

- событие добавляется в той же транзакции, что и изменение задачи;
- существующее событие нельзя редактировать или удалять через приложение;
- секреты, сессионные токены и лишние персональные данные не попадают в событие;
- системное событие может не иметь пользователя-инициатора.

### Notification

Внутреннее уведомление конкретного пользователя.

Основные данные:

- получатель;
- рабочее пространство;
- необязательная связанная задача;
- тип и безопасная полезная нагрузка;
- время создания и прочтения;
- ключ идемпотентности.

Инварианты:

- получатель является участником указанного рабочего пространства на момент создания;
- уведомление не является источником истины о состоянии задачи;
- повторная обработка одного события не создаёт дубликаты уведомлений;
- удаление доступа пользователя не должно раскрывать ему новые данные через уведомления.

## Матрица прав MVP

| Действие | Owner | Admin | Member | Viewer |
|---|:---:|:---:|:---:|:---:|
| Просматривать рабочее пространство и проекты | ✓ | ✓ | ✓ | ✓ |
| Приглашать и удалять участников | ✓ | ✓ | — | — |
| Назначать или снимать роль `OWNER` | ✓ | — | — | — |
| Создавать и архивировать проекты | ✓ | ✓ | — | — |
| Управлять спринтами | ✓ | ✓ | — | — |
| Создавать и изменять задачи | ✓ | ✓ | ✓ | — |
| Архивировать задачи | ✓ | ✓ | — | — |
| Добавлять комментарии и наблюдателей | ✓ | ✓ | ✓ | — |
| Читать архивированные ресурсы | ✓ | ✓ | ✓ | ✓ |

Дополнительные ограничения:

- администратор не может удалить владельца или изменить его роль;
- пользователь не может повысить собственные полномочия;
- проверка роли всегда выполняется в контексте конкретного рабочего пространства;
- наличие идентификатора ресурса само по себе не предоставляет доступ.

## Границы согласованности

Операции, которые выполняются одной транзакцией:

1. Создание рабочего пространства и членства его первого владельца.
2. Принятие приглашения, создание членства и пометка приглашения как принятого.
3. Создание задачи, выделение следующего номера и запись события истории.
4. Изменение задачи и добавление соответствующего события истории.
5. Запуск спринта с проверкой отсутствия другого активного спринта.
6. Завершение спринта и возврат незавершённых задач в backlog.
7. Создание доменного события для последующей отправки уведомлений.

Права доступа, членство, номера задач и изменения состояния требуют строгой согласованности. Создание и доставка уведомлений могут выполняться асинхронно: временная задержка уведомления допустима, потеря основного изменения — нет.

## Границы модулей

| Модуль | Ответственность |
|---|---|
| `identity` | Пользователи, пароли и сессии |
| `workspace` | Рабочие пространства, членство, роли и приглашения |
| `project` | Проекты и их ключи |
| `sprint` | Жизненный цикл спринтов и планирование задач |
| `issue` | Задачи, переходы, наблюдатели, комментарии и история |
| `notification` | Формирование, доставка и чтение уведомлений |

Это логические границы модульного монолита, а не отдельные сервисы. Модули выполняются в одном Go-приложении и используют одну PostgreSQL, но взаимодействуют через явно определённые сценарии и не изменяют внутренние данные друг друга напрямую.

## Отложенные решения

Следующие возможности не входят в текущую модель и потребуют отдельного изменения требований:

- закрытые проекты с отдельным списком участников;
- настраиваемые статусы и workflow;
- несколько исполнителей задачи;
- подзадачи и связи между задачами;
- метки и компоненты;
- вложения;
- редактирование и удаление комментариев;
- несколько одновременно активных спринтов;
- внешние интеграции.

## Следующий шаг

На основании этой модели необходимо описать первые прикладные сценарии: `RegisterUser`, `CreateWorkspace`, `InviteMember`, `AcceptInvitation`, `CreateProject`, `CreateIssue`, `StartSprint`, `TransitionIssue` и `CompleteSprint`. Для каждого сценария будут определены входные данные, проверки, изменения состояния, ошибки и граница транзакции.
