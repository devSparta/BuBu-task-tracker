# UC-006: CreateProject

Статус: `Draft v0.1`

## Цель

Создать проект внутри рабочего пространства с неизменяемым коротким ключом для человекочитаемых номеров задач.

## Актор

Активный участник рабочего пространства с ролью `OWNER` или `ADMIN`.

## Предусловия

- Workspace существует.
- У пользователя есть активное членство в этом workspace.
- Сессия действительна, CSRF-проверка пройдена.

## Входные данные

| Поле | Обязательность | Правило |
|---|:---:|---|
| `workspace_id` | да | Идентификатор workspace из маршрута |
| `name` | да | После trim от 1 до 120 символов |
| `key` | да | От 2 до 10 символов, начинается с `A–Z`, далее `A–Z` или `0–9` |

Ключ нормализуется в верхний регистр до проверки уникальности.

## Результат

- Создан неархивированный `Project`.
- Проект принадлежит указанному workspace.
- Счётчик следующего номера задачи инициализирован значением `1`.

## Основной сценарий

1. Система аутентифицирует пользователя и проверяет CSRF.
2. Загружает workspace только в разрешённом пользователю контексте.
3. Проверяет активное членство и роль `OWNER` или `ADMIN`.
4. Валидирует название и нормализует ключ.
5. Проверяет уникальность ключа внутри workspace.
6. Создаёт проект с начальным счётчиком задач.
7. Возвращает проект.

## Альтернативные сценарии и ошибки

| Условие | Результат |
|---|---|
| Workspace отсутствует или скрыт политикой доступа | `404 WORKSPACE_NOT_FOUND` |
| Недостаточная роль | `403 INSUFFICIENT_ROLE` |
| Некорректные имя или ключ | `422 VALIDATION_FAILED` |
| Ключ уже используется в этом workspace | `409 PROJECT_KEY_ALREADY_EXISTS` |
| Параллельная вставка того же ключа | То же `409`, обеспеченное уникальным ограничением |
| Ошибка хранилища | Откат и `500 INTERNAL_ERROR` |

Одинаковый ключ может использоваться в разных рабочих пространствах.

## Бизнес-инварианты

- Проект принадлежит ровно одному workspace.
- Ключ уникален внутри workspace.
- Проект нельзя перенести в другое рабочее пространство.
- После создания первой задачи ключ проекта нельзя изменить.
- Все активные участники workspace видят неархивированный проект.

## Авторизация

| Роль | Разрешение |
|---|:---:|
| `OWNER` | да |
| `ADMIN` | да |
| `MEMBER` | нет |
| `VIEWER` | нет |

## Граница транзакции

Создание проекта выполняется одной транзакцией. Уникальность пары `workspace_id + key` обеспечивается базой данных, а не только предварительной проверкой.

## События и аудит

- Создание проекта фиксируется в бизнес-аудите с автором и workspace.
- `IssueEvent` не создаётся.
- Outbox не обязателен, пока для создания проекта нет асинхронных подписчиков.

## Требования безопасности

- `workspace_id` всегда проверяется совместно с membership текущего пользователя.
- Поля `archived_at`, счётчик задач и автор аудита устанавливаются сервером.
- Неизвестные поля запроса отклоняются или игнорируются по единой политике API.
- Ответ не содержит внутренние счётчики и технические данные.

## Критерии приёмки

1. `OWNER` и `ADMIN` создают проект.
2. `MEMBER`, `VIEWER` и пользователь другого workspace получают отказ.
3. Дубликат ключа в одном workspace отклоняется.
4. Тот же ключ разрешён в другом workspace.
5. Новый проект не архивирован, а следующий номер задачи равен `1`.
6. Проект виден всем активным участникам workspace.

## Тесты

- Unit: нормализация и формат ключа.
- Integration: уникальность ключа в пределах workspace и начальный счётчик.
- Authorization: матрица ролей и cross-workspace доступ.
- E2E: создание проекта владельцем и появление проекта у участника.
